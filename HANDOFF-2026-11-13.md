# Handoff: the Fable 5.2 session of 2026-11-12 to 2026-11-13

A record of what one long session (Claude Fable 5.2, high effort) built and
measured, for whoever works on Neuromesh next. It is facts, not a plan. The
live handoff for the project is `HANDOFF.md`; this file covers an earlier
stretch, written down on 2026-11-19 from the session's own record.

The project moved a long way after this session (the routing cascade,
`cascade-claude` as the default, F80 to F132, SWE-bench-Live, the lead and K6
designs). Nothing here overrides that. Where this file and later work
disagree, the later work is current.

- Goal, as the owner stated it: minimise total trajectory cost while matching
  or exceeding the resolution rate of a single frontier model. Cost first
  (plan quota, then dollars at API list prices), time second.
- The branch in use was `neuromesh-testing`; `~/.neuromesh/app` was a checkout
  of it. Plan: Claude Pro.
- GPT-6 Luna was unavailable to the owner during this session; Gemini Flash

## Fault harness facts

- A seeded run of the engine against fake agents that misbehave (crash, hang,
  write outside their files, leave processes, damage the worktree), checked
  against a list of rules after every run. A `--kill 1` mode kills the engine
  process at a turn and resumes it.
- Before the fixes it found: an endless loop in the checks step, a race
  between tasks merging and checks (F75), adapter crashes ending runs (F74),
  worktree damage (F73), a half-written event line, a leftover process holding
  the output pipe (F76).
- After the fixes in this session: 1,000 ordinary seeds and 400 kill seeds kept
  every rule, run several times, the last on the F79 code.
- Two kill-seed reports late on 11-13 were harness faults: a kill landing after
  the run had been applied, and the dependency-order rule not knowing that a
  resumed run only sees events since the resume.

## Quota finding

Haiku 5.5 is about 5 to 7 times cheaper than Opus 5.5 per token of the Claude
plan's quota, not about 40 times as at API list prices. An Opus+Haiku team on
one Claude plan therefore saves quota only by using fewer tokens, not by moving
tokens to Haiku. (Memory: `fault-harness-and-quota-finding.md`.)

## The hard task: `hard-py-minidb`

A pure-Python SQL engine whose answers must equal SQLite's. 197 hidden cases in
12 groups (expressions, select, aggregate, join, subquery, union, write,
errors, transactions, speed, saving, command line). Every expected answer comes
from the real SQLite at check time. The package runs in a child process where
`sqlite3` cannot be imported. A stand-in that wraps SQLite scores 197/197 with
the block off and 0/197 with it on. Python 3.9, standard library only.

### `hard-tiers-1` turn by turn

| Role | Task | Model | Minutes | Output tokens | Est. $ |
| --- | --- | --- | --- | --- | --- |
| scout | - | Haiku | 0.4 | 4.9K | 0.00 |
| spec and plan | - | Opus | 2.8 | 16.8K | 0.45 |
| T1 lexer, AST, parser (senior) | T1 | Sonnet | 2.3 + 0.1 repair | 23.2K | 0.40 + 0.02 |
| T2 value rules (senior) | T2 | Sonnet | 3.6 | 29.6K | 0.57 |
| T3 storage, undo log, saving (senior) | T3 | Sonnet | 1.0 | 9.3K | 0.18 |
| T4 query executor (expert) | T4 | Opus | 11.5 | 64.4K | about 2.56, cut at the $3 budget; work kept, checks passed |
| T5 database engine (senior) | T5 | Sonnet | 1.4 | 12.7K | 0.30 |
| T6 CLI, README, differential and timing tests (worker) | T6 | Haiku | 3.5 + 0.5 repair | 53.1K | 0.05 |
| review loop on T6: 4 reviews, 3 fix turns | T6 | Sonnet reviews, Haiku fixes | 21 | 231K | about 1.3 |

- Opus chose the tiers itself: the executor for itself, four parts for Sonnet,
  one for Haiku. Executor 1,200 lines; values 661; parser 574.
- The review loop: Sonnet's whole-program review found that the float-to-text
  rule differed from SQLite in the 17th digit (`CAST(1/3.0 AS TEXT)`) and that
  `CAST('-0' AS REAL)` gave 0.0. The flaw was in `minidb/values.py`, built by
  Sonnet (T2). The fix went to Haiku (T6's worker). Haiku first listed it in
  the README as a known difference and marked its test as an expected failure,
  then took a 13-minute climb turn (134K output) and a 6-minute fix turn. The
  fourth review passed. The hidden battery does not test that digit, so the
  loop most likely did not change the hidden score; this was not measured.
- The dollar figures per model in `results.json` do not add up to the summary's
  $6.02: a turn cut at the budget is recorded with unknown cost, and resumed
  sessions report cumulative cost. Tokens and times are right.

## Observations that were not acted on in this session

- The $3 expert budget was used up by Opus's one part on the hard task; the
  part was finished just before the cut.
- Fable 5.2 at high effort thought for about 15 minutes before writing any code
  on the hard task, at about 2 points of a Pro 5-hour window per minute.
- An earlier AQI run (`~/Projects/bench-aqi`, uncommitted there) produced a
  spec whose regression target was computed from its own inputs, despite the
  scout's facts warning about it. No engine fix was made.
- This session itself used a large share of the plan: a conversation of
  several hundred thousand tokens on Fable re-reads its context on every turn,
  most heavily after the cache expires. On 11-13 it caused one 5-hour limit hit
  mid-benchmark and polluted the quota readings of runs made while it was
  active.
