build a small SQL database engine in pure python, as a package called `minidb`, that i can use from my own programs instead of sqlite for small jobs. it should run the usual SQL (create table, insert, update, delete, select with joins, grouping, sorting, subqueries, transactions), keep its data in a file, and give exactly the answers SQLite gives. include tests

Details that must hold:

- Python 3.9, standard library only. The package must not use the `sqlite3` module (your tests may use it to compare answers).
- `from minidb import Database, SQLError`. `Database()` is an empty in-memory database; `Database(path)` opens the file at `path` and creates it when it is missing. `db.execute(sql)` runs one statement (a trailing `;` is allowed) and returns a list of tuples: the rows of a `SELECT`, and `[]` for every other statement. Values are `int`, `float`, `str` or `None` and nothing else (true and false are the integers 1 and 0). `db.close()` closes it.
- **The answers are SQLite's.** For the SQL listed below, the rows, the values and the value types (`3` is not `3.0`) are what SQLite 3 returns for the same statements on the same data: NULL handling, integer and real arithmetic, text comparison, sort order, what aggregates return on no rows, what the functions return, and so on. Rows come back in the `ORDER BY` order when there is one, and in any order otherwise.
- A statement that SQLite rejects raises `SQLError` with a readable message: bad syntax, an unknown table, column or function, an ambiguous column name, a broken constraint, the wrong number of values, a table or index that already exists or does not exist, `BEGIN` inside a transaction, `COMMIT` or `ROLLBACK` with none open. A statement that fails changes nothing, even when it had already changed some rows, and an open transaction stays open.
- Statements:
  - `CREATE TABLE [IF NOT EXISTS] name (column TYPE [PRIMARY KEY] [NOT NULL] [UNIQUE] [DEFAULT literal], ...)` with the types `INTEGER`, `REAL` and `TEXT`; `DROP TABLE [IF EXISTS] name`.
  - `CREATE INDEX [IF NOT EXISTS] name ON table (column, ...)`; `DROP INDEX name`.
  - `INSERT INTO table [(column, ...)] VALUES (...), (...)` and `INSERT INTO table [(column, ...)] SELECT ...`.
  - `UPDATE table SET column = expr, ... [WHERE expr]`; `DELETE FROM table [WHERE expr]`.
  - `SELECT [DISTINCT] item, ... [FROM source] [WHERE expr] [GROUP BY expr, ...] [HAVING expr] [ORDER BY term [ASC|DESC], ...] [LIMIT n [OFFSET m]]`. An item is `*`, `table.*` or `expr [[AS] alias]`. An `ORDER BY` term is an expression, an output alias or an output column number.
  - A source is `table [[AS] alias]` or `(SELECT ...) [AS] alias`, combined with `,`, `CROSS JOIN`, `[INNER] JOIN ... ON expr` and `LEFT [OUTER] JOIN ... ON expr`.
  - `SELECT ... UNION [ALL] SELECT ...`, with one final `ORDER BY` and `LIMIT` for the whole.
  - `BEGIN`, `COMMIT`, `ROLLBACK`.
- Expressions: whole and decimal numbers, `'text'` (with `''` for a quote), `NULL`; `column` and `table.column`; `+ - * / %` and unary `-`; `||`; `= == != <> < <= > >=`; `AND`, `OR`, `NOT`; `IS [NOT] NULL`; `[NOT] BETWEEN a AND b`; `[NOT] IN (value, ...)`; `[NOT] IN (SELECT ...)`; `[NOT] LIKE pattern`; `CASE [expr] WHEN ... THEN ... [ELSE ...] END`; `CAST(expr AS INTEGER|REAL|TEXT)`; `EXISTS (SELECT ...)`; `(SELECT ...)` used as a value. A subquery may use the columns of the query around it. Functions: `ABS`, `LENGTH`, `UPPER`, `LOWER`, `SUBSTR`, `COALESCE`, `IFNULL`, `NULLIF`, `ROUND`, `TYPEOF`, and the aggregates `COUNT(*)`, `COUNT(x)`, `COUNT(DISTINCT x)`, `SUM`, `AVG`, `MIN`, `MAX`. Keywords and function names are accepted in any letter case.
- An `INTEGER PRIMARY KEY` column that is left out of an `INSERT`, or given NULL, gets the next whole number: one more than the largest in the table, starting at 1. A whole number stored in a `REAL` column comes back as a float.
- Saving: outside a transaction every statement is saved to the file as it finishes. `BEGIN` opens a transaction, `COMMIT` saves it, and `ROLLBACK` throws its changes away, including tables created or dropped in it. A program that exits or crashes without `COMMIT` loses only the open transaction. Another process that opens the file afterwards sees the saved data, with its constraints, defaults and indexes. The file format is yours to choose.
- Speed, on an in-memory database on a laptop, each within 5 seconds (loading the rows is not timed, but takes seconds, not minutes):
  - a join of two 5,000-row tables on an equality between columns that have no index, and a `WHERE x IN (SELECT ...)` between two such tables;
  - 2,000 single-row `SELECT`s or `UPDATE`s that find their row by primary key or by an indexed column in a 20,000-row table;
  - `GROUP BY` with aggregates, `COUNT(DISTINCT ...)` and `ORDER BY ... LIMIT` over 20,000 rows.
- Command line: `python3 -m minidb DBFILE "SQL"` runs the statements in the string, separated by `;` (a `;` inside quoted text does not separate), against the database file, and prints each row of each `SELECT` on its own line: values joined by `|`, NULL as nothing, other values as Python's `str()` gives them. On an error it prints `Error: <message>` to stderr and exits with status 1; the statements before the failing one stay done and the rest are not run.
