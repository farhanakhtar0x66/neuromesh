Anpasser's source-flow analysis (`tools/subsystem_flow.py`, used by `tools/native_subsystems.py` to prove that a game's window classes are closed) gives up whenever the original program calls one of its own small functions in the middle of building a window class: after any call, `call_arguments` forgets every register and every memory fact it had, so a class descriptor that is filled in around a call to a tiny getter is never proved. Teach it to summarise the simplest source functions, read-only leaves, from their actual P-Code instead of guessing, and to use those summaries.

Functions are dicts `{"address", "instructions": [{"address", "fallthrough"?, "operations": [...]}]}` with Ghidra P-Code operations (`opcode`, `inputs`, optional `output`, optional `memory_space`); varnodes are `{"space", "offset", "bytes"}`. Register 16 is `ESP`, 644 the instruction pointer, and the general registers are 0, 4, 8, 12, 16, 20, 24 and 28 (4 bytes each).

1. New `leaf_effects(function)` in `tools/subsystem_flow.py`. It walks the function's straight-line code from its first instruction by `fallthrough`, tracking for each 4-byte general register a symbolic value: it starts as `("input-register", n)`; constants are `("constant", value)`; a 4-byte `ram` operand read is `("source-read", ("constant", address))`; a `LOAD` from `ram` of an address value `a` is `("source-read", a)`; `COPY` copies a value; `INT_ADD` and `INT_SUB` of a value and a 4-byte constant give `("constant", sum mod 2^32)` for two constants, or a running `("sum", base, offset)` (offsets are signed 32-bit, a `INT_SUB` subtracts) otherwise. It returns `None` (no summary, "refuse") for anything it cannot account for: more than 32 instructions or none; any operation whose output is not a 4-byte `unique` or `register` varnode; an output register that is not one of the general registers or 644; any opcode other than `COPY`, `INT_ADD`, `INT_SUB`, a `ram` `LOAD` or the final `RETURN`; an operand that is not 4 bytes wide or has an unknown value; a value whose text form exceeds 1,024 characters; a function that never reaches a `RETURN` or whose instructions are not all visited; and any `STORE`, `CALL` or branch (these are not in the allowed opcode set). The `RETURN` must be the last operation of its instruction and must return the value `("source-read", ("input-register", 16))`, that is the return address read from the original stack top. At the end `ESP` must be `("sum", ("input-register", 16), delta)` with `delta` a multiple of 4 between 4 and 260 inclusive.
   On success it returns `{"argument_bytes": delta - 4, "memory_effect": "read", "analysis_only": True, "source_stack_delta": delta, "preserved_registers": <sorted general registers other than ESP whose final value is still their own input value>, "register_results": {register: final symbolic value for every other general register except ESP that is not preserved}, "proof": "closed-readonly-leaf-with-source-return-address-and-register-effects"}`. For a getter that does `MOV EAX,[0x405000]; RET` this is a `source_stack_delta` of 4, `register_results` `{0: ("source-read", ("constant", 0x405000))}` and the other registers (including 8) preserved.
2. `call_arguments` gets an optional `leaf_contracts` mapping (function address to such a summary; default empty). At a direct `CALL` to a `ram` address that has no import signature or site contract, the leaf summary is the call's contract. After the call, only the registers the contract says are preserved (default: the callee-saved set, as today) survive; each entry of `register_results` is evaluated against the facts and memory at the call site (`input-register` n is the caller's value of register n, `source-read` reads source memory through the caller's memory model, `sum` adds a constant) and becomes the new value of that register when it can be evaluated; `ESP` advances by the contract's argument bytes plus 4, as for other contracts. A contract whose `memory_effect` is `read` or `none` also keeps the caller's known memory facts, as read-only calls already do. When the arguments of a call are collected, a constant (not only a stack object) passed as an argument is also snapshotted as an object of 32 words read from the constant address, so a descriptor in constant storage can be recovered when it is built on the stack by earlier code.
3. In `discover` (`tools/native_subsystems.py`): compute `leaf_effects` for every function in the first pass and pass the map as `leaf_contracts` to `call_arguments`; skip functions that are import thunks as analysis roots (direct callers supply the source frame); and when a class descriptor address is a constant but the bytes at that address are not read-only, accept a descriptor that earlier code constructed there when the proved argument object for it has its second and tenth words proved (use that object's constant words as the descriptor fields), instead of refusing it. Keep refusing with "class descriptor is not immutable or a proved constructed object" otherwise, and refuse a null class callback ("null class callback"). The returned report gains `readonly_leaf_contracts`, the number of functions that have a leaf summary.

The new tests check: the getter above gives the summary described (delta 4, one register result, register 8 preserved) and `None` when a `STORE` to its address, a `CALL`, a 1-byte `COPY`, or a `RET` that reads its return address through `EAX` instead of `ESP` is added; and that a class whose descriptor is a constant-address stack-built object is proved (`closed_windows` true, `classes[0]["descriptor"]` equal to that address).
