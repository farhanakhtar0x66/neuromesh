DroidTUI is a terminal UI for Android developers built on `ratatui`. Today every menu entry carries a shell command as a plain `String` (`MenuItem::command` and `MenuChild::command` in `src/menu.rs`), `src/update.rs` runs those strings, and the code that talks to the device is spread over the menu, the update loop and the streaming code. There is no library to reuse from outside the binary: `Cargo.toml` already declares a `[lib]` named `droidtui` at `src/lib.rs`, but the file does not exist, so the crate does not build as a library and nothing can be tested from `tests/`.

Refactor to a typed ADB layer and a real library crate.

1. Add `src/lib.rs`, the library root of the `droidtui` crate, declaring these public modules: `adb` (new), `app`, `effects`, `event`, `menu`, `message`, `model`, `stream`, `update` and `view`. Keep `src/main.rs` as the binary, now using the library (`use droidtui::...`) instead of declaring the modules itself. `cargo build` must still produce the same binary.
2. Add `src/adb.rs`, a typed client abstraction over the `adb_client` crate that is already a dependency, with these public items:
   - `pub type AdbResult<T> = Result<T, AdbError>;`
   - `pub enum AdbError` (derives `Debug`, implements `std::fmt::Display` and `std::error::Error`) with the variants `ConnectionError(String)`, `DeviceNotFound`, `CommandFailed(String)`, `IoError(std::io::Error)`, `ParseError(String)` and `NoDeviceSelected`. Display texts: "Connection error: <msg>", "Device not found", "Command failed: <msg>", "IO error: <error>", "Parse error: <msg>", "No device selected". `From<std::io::Error>` gives `IoError`; `From<adb_client::RustADBError>` gives `CommandFailed` with the error's text.
   - `pub enum AdbCommand` (derives `Debug`, `Clone`) with the variants `ListDevices`, `GetDeviceState`, `GetSerialNumber`, `ListPackages { include_path: bool, filter: PackageFilter }`, `GetPackageInfo { package_name: String }`, `InstallPackage { apk_path: String }`, `UninstallPackage { package_name: String }`, `ClearPackageData { package_name: String }`, `GetBatteryInfo`, `GetMemoryInfo`, `GetCpuInfo`, `GetDeviceProperties`, `GetSystemLog { lines: usize }`, `GetNetworkInfo`, `GetWifiStatus`, `TakeScreenshot`, `GetScreenResolution`, `ListProcesses`, `ForceStop { package_name: String }`, `Shell { command: String }` and `GetAdbVersion`.
   - `pub enum PackageFilter` (derives `Debug`, `Clone`) with `All`, `User` (`pm list packages -3`), `System` (`-s`), `Enabled` (`-e`) and `Disabled` (`-d`).
   - `pub struct DeviceInfo { pub serial: String, pub state: String, pub model: Option<String>, pub device: Option<String> }` (derives `Debug`, `Clone`).
   - `pub struct AdbManager` (derives `Debug`) with `AdbManager::new()` (creating one must not connect to anything or panic), `connect(&mut self) -> AdbResult<()>` (the ADB server on 127.0.0.1:5037, created lazily by `execute` when needed), `select_device(&mut self, serial: String)` and `execute(&mut self, command: AdbCommand) -> AdbResult<String>`, which runs the command and returns its output as text. Commands that need a device return `AdbError::NoDeviceSelected` when none is selected; with the server unreachable they return an error and never panic. Each command maps to the natural `adb shell` call (for example battery info is `dumpsys battery`, memory `cat /proc/meminfo`, processes `ps`, screen resolution `wm size`, system log `logcat -d -t <lines>`, force stop `am force-stop <package>`, clear data `pm clear <package>`), and `ListDevices` and `GetAdbVersion` use the server's own calls.
3. Use it. `MenuItem` and `MenuChild` carry an `AdbCommand` instead of a command string (items that are not ADB commands, such as the dev-mode and streaming entries, keep working as they do now), and `src/update.rs` executes menu commands through an `AdbManager` held in the model instead of building shell strings. Behaviour of the UI stays as it is.
4. Add runnable examples under `examples/` (device info, main menu, package manager and streaming) that use the library API, and a `just` recipe for each; they are documentation and are not graded.

Graded by a new integration test file, `tests/adb_integration_tests.rs` (not in your copy of the repository), which uses `droidtui::adb::{AdbCommand, AdbError, AdbManager, PackageFilter}` only: it builds every command variant and the five filters, clones a command and matches on it, checks the `Debug` output names the variant, checks the error display texts above and that an `io::Error` converts into `AdbError::IoError`, builds an `AdbManager`, and destructures `Shell { command }` and `ListPackages { include_path, filter }`. The tests that need a real device are marked `#[ignore]` and do not run.
