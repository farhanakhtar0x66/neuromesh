Anpasser's COM object-flow recovery (`recover_object_flow` in `tools/com_analysis.py`) runs a bounded fixed-point over the functions of a converted game's whole-program recovery. Today every function that contains any indirect call or branch (`CALLIND`/`BRANCHIND`) or a direct call to an import thunk is a candidate, so a real game with thousands of unrelated math and C-runtime functions makes the analysis run the expensive symbolic argument recovery (`subsystem_flow.call_arguments`) on all of them, even though none of them can ever contribute a COM factory origin. Make the analysis demand-driven without changing what it proves.

Behaviour to implement:

- A function is only analysed (passed to `call_arguments`) if it can contribute to a source COM object origin:
  - it is a *factory caller*: it mentions, as a 4-byte `ram` or `const` operand, the import slot address of a known factory import, or the address of an import thunk that forwards to one (the thunks come from `import_thunks`, as today); or
  - from the second iteration of the fixed point on, it mentions, as such an operand, a storage cell that already holds a recovered object binding (a binding whose location is a `constant` cell), or it mentions the address of a *getter*: a source function whose leaf summary (`leaf_effects`) returns a value read from such a cell (the cells read by its `register_results` expressions).
  Functions that satisfy none of this are never loaded into the symbolic solver. The candidate set is recomputed at each iteration from the cells known so far, so an object found in iteration one can pull in the users of its storage in iteration two. The iteration limit, the rejection rules and everything that is already proven stay as they are.
- Source call effects: compute `leaf_effects` once per function in the existing first pass over the functions (when it returns nothing and the caller asked for guarded returns, fall back to `normal_return_contract`), and keep the per-function sets of 4-byte `ram`/`const` operand values it needs for the demand test, so no function is loaded twice for the demand decision.
- The report returned by `recover_object_flow` gains two integers: `analyzed_functions`, the number of distinct functions that were actually handed to `call_arguments` over the whole run, and `source_functions`, the number of functions in the input. Existing keys keep their meaning.
- With no factory imports at all (an empty `imports`), `call_arguments` must never be called and no method calls are reported.

Graded by new tests in `tools/test_com_object_flow.py` (not in your copy of the repository; the whole file runs under pytest). The new test builds the usual small fixture with one factory call, a thunk and two connected method calls, adds 200 unrelated functions, each with a `CALLIND` through `EAX` and a `RETURN`, wraps `subsystem_flow.call_arguments` with `unittest.mock.patch(..., wraps=...)`, and expects: two accepted method calls, none of the 200 unrelated addresses ever passed to `call_arguments`, `analyzed_functions` below 10 and `source_functions` equal to 204; then, with `imports={}`, no call at all and no method calls. Every other test of that file, and of `tools/test_native_subsystems.py` and `tools/test_subsystem_flow.py`, must keep passing.
