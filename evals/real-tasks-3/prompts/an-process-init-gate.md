Anpasser converts a recovered Windows game into a native Linux or macOS program. Two gaps in the standalone toolchain let it produce a program that looks complete but is not, and one makes the toolchain cache trust more than it checked. Close them.

1. Unmigrated process initialization must block native emission. A PE file can carry initialization that runs before `main` and that the converter has no migration for: TLS callbacks (data directory index 9), load configuration (10), delay-import tables (13) and the managed CLR header (14). When the recovered module inventory (`module/analysis-inventory.json`, key `inventory.directories`, a list of `{index, rva, size}`) has a non-empty directory with one of those indices, `tools/whole_program.py` `prepare(project)` must put an entry for it into a new `process_semantics_blockers` list of the whole-program report (`whole-program.json` and the returned dict; an empty list when there are none): `{directory: <index>, rva: <rva>, bytes: <size>, reason: "<name> has no native migration"}` with the names "Windows TLS initialization/callbacks", "Windows load-configuration initialization", "Windows delay-import initialization" and "managed CLR execution". Then `tools/build_whole_program.py` `build(project, compiler, ...)` must refuse to build when the report has any: it records an error containing "unmigrated process initialization; see process_semantics_blockers in whole-program.json" in its result, emits no package (`package_emitted` false), creates no `build/native-program`, and never runs the compiler (the compiler argument may be a name that does not exist). This check happens before the frozen-source and hash checks. On the Rust side, `src/whole_game.rs` should count them in the `known_blockers` of its result as `process_semantics`, and when the conversion attempt fails it should return an error that says "conversion incomplete" and names the `result.json` report and the blockers instead of the bare error.
2. The cached SDK must be exactly what was recorded. `tools/resolve_toolchain.py` `sdk(cache, profile, offline)` already refuses a cache whose lock files changed ("native SDK lock changed; use a fresh --tool-cache") and whose recorded files changed ("native SDK file changed: <name>"). It must also compare the set of regular files and the set of symlinks that actually exist under the SDK root with the recorded `files` and `symlinks` of the identity marker, and raise `ValueError("native SDK inventory changed")` when they differ (an extra file or link, or a missing one). The inventory check comes after the lock check and before the per-file checksums.
3. The compiler and linker can be chosen. `resolve(cache, phase, offline=False, profile='base', compiler=None, linker=None)` uses the given compiler instead of the discovered `clang`, and the given linker instead of `ld.lld` from `PATH` or the rustup toolchain; the command line gains `--compiler` and `--linker`. On the Rust side `whole_game::convert` passes `--compiler`/`--linker` to the build phase only when they differ from the default `clang` and the unset linker, and records the number of native library bindings (`native_library_bindings`) in its result. `src/main.rs` should keep working with these changes (`cargo build` and `cargo test` must still pass).

Graded by Python tests only: a new file `tools/test_toolchain.py` (a cache directory in a temporary folder with a `linux-amd64/toolchain-identity.json` marker, a `sysroot` tree, an unexpected file that must be reported as an inventory change, a modified file, and a modified lock hash) and a new test in `tools/test_whole_program.py` that edits the fixture's inventory so it contains directory index 9 with a non-zero size, calls `prepare`, expects one blocker, then calls `build(p, 'must-not-execute-compiler')` and expects the error text to contain "process initialization", no emitted package and no native program. The existing tests of those files, and `tools/test_native_libraries.py`, must still pass.
