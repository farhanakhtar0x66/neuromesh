EdgeMed's asset provisioning script, `scripts/provision_assets.py`, can only run on a macOS ARM64 machine: `main()` refuses to do anything on another platform, even though most of what it downloads (the pinned ONNX embedding model that the retrieval tests need) is portable. CI on Linux therefore cannot provision the model, and the retrieval tests there fail with a vague error. Make the script usable for the model alone, and make the failures easier to act on.

1. `main` takes an optional list of arguments, `main(argv=None)`, and parses them with `argparse`. It understands one flag, `--model-only`: provision only the pinned model files listed in `assets-manifest.json` (the entries whose path contains `/snapshots/`, downloaded from the pinned Hugging Face revision exactly as today, with the same checksum verification, and skipped without any request when a file is already present with the right checksum), print "Pinned model assets verified; runtime records, keys and server binaries were not changed." and return without creating the `.tools` directory or touching the Qdrant server binary. Entries of the manifest that are not model snapshots (for example `.tools/qdrant`, whose hash is platform specific) are ignored in this mode.
2. Without `--model-only`, nothing changes for macOS ARM64. On any other platform the full run must still refuse, but with a message that points at the new flag: "Full runtime assets support macOS ARM64 only. For retrieval tests, use --model-only." (a `RuntimeError`). The platform check keeps using the module's `platform.system()` and `platform.machine()` (the tests replace those two functions on the module's `platform` import, so keep `import platform` and call them through it).
3. Keep the module-level names that tests patch or read: `ROOT` (the repository root, used to find `assets-manifest.json` and as the base of downloaded paths), `REVISION`, `urlopen` and `download(url, path, expected)`. `download` already refuses a checksum mismatch and leaves an existing file untouched when it does; do not change that.
4. In `edgemed/retrieval.py`, `local_embedder` raises when the pinned model file is missing. Make its message tell the operator what to do: "Pinned local embedding model is missing. From the repository root, provision it online with: uv run python scripts/provision_assets.py --model-only. Runtime will not download it."
5. In `pyproject.toml` the pytest marker `integration` is described as requiring "the cached ONNX model and native Qdrant Server"; the tests now use the embedded Qdrant Edge, so describe it as "requires the pinned local ONNX model and embedded Qdrant Edge". Mark `test_fifty_synthetic_paraphrases_find_expected_category` in `tests/test_relevance.py` with `@pytest.mark.integration` (import `pytest`), since it needs the real model.

Graded by a new test file, `tests/test_provision_assets.py` (not in your copy of the repository). It checks, with a manifest in a temporary directory and `urlopen` replaced by a function that serves synthetic bytes: a `--model-only` run on a patched "Linux x86_64" downloads exactly the two model files, writes them under the snapshot path, does not create `.tools`, and a second run makes no request; a full run on a patched Linux platform raises a `RuntimeError` whose message mentions `--model-only`; and a checksum failure in `download` raises "checksum mismatch", keeps the previous file and leaves no `.download` file behind.
