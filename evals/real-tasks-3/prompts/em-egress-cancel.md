EdgeMed's outbound sync has a hole. `Transport.run` in `edgemed/sync.py` walks the outbox and, just before each item leaves the device, re-checks the canonical memory it points to: an item is cancelled (state `cancelled`, error "Policy no longer permits sharing") if the memory is not a synthetic fixture or is not `PUBLIC`. That re-check loads the memory with `self.store.get(payload["memory_id"], include_deleted=True)`, and `Store.get` raises `KeyError` when the memory cannot be found for the operator, for example when the outbox row points at a memory that was never shared by the operator or was created by a staff account. Today that `KeyError` is not handled where it happens. It is swallowed by the broad `except Exception` at the end of `run`, which marks the whole attempt as a verification error ("Synchronization verification failed; sharing stopped for this attempt."), leaves the offending outbox row in state `pending` forever, and stops every later item and the pull from running.

Fix it so that an outbox item whose memory cannot be found is cancelled exactly like an item whose memory is not shareable: the row ends in state `cancelled` with the error "Policy no longer permits sharing", nothing is sent to the gateway for it, and the loop carries on with the next item. Nothing else about the transport changes (acknowledged, failed and retry rows, receipt verification, the pull half).

While you are in the security-sensitive helpers, make two small portability fixes, because the project is being run on platforms that lack POSIX ownership calls:

- `private_write` in `edgemed/security.py` calls `os.fchmod(fd, 0o600)` unconditionally. Call it only when `os.fchmod` exists on the platform (the file is still created with mode 0o600).
- `verify_luks_mount` in `edgemed/linux_vault.py` compares the vault directory's owner with `os.geteuid()` and rejects any group or other permission bits. On a platform without `os.geteuid`, use the directory's own owner id for the owner comparison and skip the permission-bit check. On platforms that have `os.geteuid` the behaviour is unchanged: a vault not owned by the current user, or readable by group or others, is still rejected with "Vault mount must be owned by this user and accessible only to this user".
