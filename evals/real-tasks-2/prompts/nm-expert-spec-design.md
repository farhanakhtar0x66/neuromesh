A spec writer that is an expert model should write a spec and a design for every new program, not only for thin requests: that is where a strong model's judgement pays most and costs least. The workers then build from both.

- `BriefPolicy` in `src/intake/brief.ts` gets an optional `expertSpec: boolean` ("the spec writer is an expert model"). When staffing a request (`staff`), if the request is a new program (greenfield), a spec writer is available (`canSpec`) and `expertSpec` is true, `staffing.spec` is true however long or detailed the request is, with the reason "building something new: the expert writes the spec and design, workers build it". Otherwise nothing changes: a cheap writer only fills in thin requests, and a change to an existing project never gets a spec. `startRun` (`src/engine/run.ts`) and the `neuromesh brief` command (`src/cli/main.ts`) set `expertSpec` when the first model of the briefer role has tier "expert".
- `Spec` gets `design: string[]` (how to build it: the modules and what each does, the data model, the hard parts). `SPEC_SCHEMA` in `src/engine/prompts.ts` requires `design` (an array of strings), `parseSpec` returns it, and `renderBrief` adds, after the out-of-scope block, "Design, follow it unless it is clearly wrong:" followed by the points as a `- ` list (only when there are any). The spec's heading in the rendered brief becomes "Product spec and design, worked out from the request above (the request wins wherever they differ):".
- `specPrompt(request, brief?)` is now written to an expert: "You are the lead engineer. A less experienced developer is about to build the request below on their own, from what you write now; you will not see their work. Write the product spec and the design they need." It includes the full rendered brief when that differs from the request, tells the model that for an already detailed request it should not repeat it but cover only what it leaves open and put most of its effort into the design, and asks for `design`: 6 to 12 points on how to build it. The spec step passes `renderBrief(brief)` as the second argument.

Graded by new tests in `test/brief.test.ts` and `test/engine.test.ts` (not in your copy of the repository).
