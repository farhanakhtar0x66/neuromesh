Three failures seen in live hard-task runs.

1. Antigravity and Codex sometimes print their final event (`result`, `turn.completed`) and then never exit, so each such turn runs into the 30-minute limit and fails. Make the CLI runner stop a tool that lingers after its final event and keep its result. A stream parser (`StreamParser` in `src/backends/shared.ts`) gets an optional `finished?(): boolean` that says the tool has sent its last event for the turn; implement it in the Antigravity, Claude and Codex parsers (Antigravity and Claude: the parsed run has a stop reason; Codex: the turn completed or failed). `runCli` waits for the process to exit for `lingerMs` after `finished()` first becomes true (a new optional field of `CliInvocation`; the default is an exported constant `LINGER_MS`, 10 seconds), then stops it. Stopping it that way is not the person cancelling: the result stays what the parser reported (`stop: "done"` and its final text), and `cancelled` is reported only when the caller's own `signal` aborted.
2. Dropped connections ("read tcp", "connection reset", "request failed: Post", 503 `UNAVAILABLE`, and Antigravity's bare message "interrupted") are retried once, like the errors the engine already retries (the `TRANSIENT` pattern in `src/engine/run.ts`).
3. A planning turn that fails outright (an agent failure such as a timeout) no longer fails the run. The engine emits a `note` event whose message is "Planning failed (<the reason, at most 160 characters>); a worker takes the whole request.", switches the run to `solo` mode and gives a single task (id `main`, title "the request", brief = the prompt, owned files none, owner worker) to a worker; the expert stays available for escalation. A planning turn that was interrupted still interrupts the run, and other outcomes end it as before.

Graded by new tests in `test/proc.test.ts` and `test/engine.test.ts` (not in your copy of the repository).
