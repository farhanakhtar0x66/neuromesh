The fault harness found two defects in the blind-test step (F101), in kill-and-resume seeds 136, 137, 198 and 280 and in seed 398.

1. An engine that is stopped or killed while it runs the blind tester's tests on its copy asks the blind tester for them again when the run is resumed, paying for a second turn. Keep the answer with the task (`blindAnswer`, `{ tests: { path, content }[], summary }`, on the task's state, saved as soon as it arrives and its tests are usable) and, on resume at the `blind` step, run the kept tests instead of asking again. Once the tests have been judged (passed, failed or none usable) the kept answer is cleared, so `blindAnswer` is undefined afterwards. If the engine died before the answer was saved, the tester is asked again as before. A stop of the blind turn itself (cancelled, a rejected login) still stops the run.
2. A killed engine can leave the blind tester's copy (a git worktree at `<run folder>/tasks/<task id>/tester`) behind. The blind step removes a leftover copy first, before anything else, because this pass may end before it would make (and remove) its own. The race step that follows does the same for its copies when it is switched off.

Graded by new tests in `test/phase2.test.ts` (not in your copy of the repository). The scenario: a run is stopped while the blind tests run, then resumed once with the kept answer and once with it lost; the second blind turn is not paid for in the first case, and in both the leftover copy is gone.
