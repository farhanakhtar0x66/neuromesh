A tool that resumes a session can report its usage as running totals for the whole session, not for the turn: `codex exec resume` does. The engine records each resumed turn's usage as the tool reported it, so every repair turn is counted as if it repeated all the turns before it. Record usage per turn.

- In `src/backends/types.ts`, add an optional boolean `sessionTotals` to `AgentBackend` (true for a backend whose resumed sessions report running totals) and export `usageSince(totals: Usage, earlier: Usage[]): Usage`: for each of `input`, `output`, `reasoning`, `cacheRead` and `cacheWrite`, the totals' value minus the sum of the earlier turns' values, never below 0; a field the totals leave undefined stays undefined. Set `sessionTotals: true` on the Codex backend (`src/backends/codex.ts`).
- In the engine (`src/engine/run.ts`, where an attempt is recorded after a turn): when the turn resumed a session, the backend has `sessionTotals`, and the result's `sessionId` is the session that was resumed, record the attempt's usage (and the usage on the turn's finished event) as `usageSince(result.usage, <the usages already recorded for attempts of that same backend and session>)`. Any other turn is recorded as the tool reported it.
- Runs made before this hold session totals. Add an optional `usagePerTurn` flag to `RunState` (`src/engine/types.ts`), set to true on every new run, and export `perTurnAttempts(state, sessionTotals)` from `run.ts`, where `sessionTotals` says whether a backend id reports totals: it returns the attempts unchanged when `usagePerTurn` is set, and otherwise turns each resumed-session attempt into the change since that session's previous attempt. Use it in a new `recountEval(home, name)` in `src/eval/eval.ts`, which recounts an eval's per-model usage and its expert and worker token totals from its runs' records without a model call, and expose it as `neuromesh eval recount <name>...` in `src/cli/main.ts`.

Graded by new tests in `test/engine.test.ts` (not in your copy of the repository). The scenario: a fake backend with `sessionTotals` set, whose turns report growing totals for one session, must have each turn recorded as the difference from the total before it.
