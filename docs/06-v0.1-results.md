# v0.1 results

Measured on 2026-11-11 on one Mac, on subscriptions only: Gemini 3.8 Flash
through Antigravity, GPT-6.1 Sol through Codex (ChatGPT Plus), and briefly
Claude Opus 4.6 through Antigravity before its free quota ran out.

Every number below comes from `neuromesh eval` and is reproducible with the
commands at the end. Results live in `~/.neuromesh/evals/<name>/results.json`.

## The question

The goal from the start: match a frontier model's results while spending as
little of the expensive model as possible. On a subscription the binding cost
is quota, not money. After one day of evals the owner's dashboards showed
Gemini at 87% of its weekly limit left and ChatGPT Plus at 23%, even though
Gemini had processed many times more tokens. So the number that matters is
**expert tokens**: what the heavy model spends.

## The task suite

25 tasks with hidden tests the agents never see. A task passes only if its
hidden check passes after the run's diff is applied.

| Kind | Tasks |
| --- | --- |
| Bug fixes | 5 (JavaScript, Python, Rust) |
| Features | 5 (JavaScript, TypeScript, Python, Rust) |
| Multi-part features | 4 |
| Refactors | 2 |
| Greenfield tools | 2 |
| Trivial requests | 2 |
| Hard (subtle semantics) | 4: cron next-run, LRU cache with TTL and shared loads, expression parser with exact error positions, minimal unified diff |
| Large (five parts) | 1: a shop library with a receipt CLI |

Each hard and large task's hidden check was validated against a reference
implementation kept outside the repository. That mattered: four "model
failures" during the day turned out to be bugs in the checks themselves (a
Python import path, a query that matched by accident, an ambiguous rounding
case), all fixed and re-scored with `neuromesh eval recheck`.

## Baselines

Per-task averages. "Fresh" expert tokens are fresh input plus output; "all"
also counts cache reads, which cost far less quota.

| Configuration | Passed | Expert tokens, fresh | Expert tokens, all | Worker tokens, all | Minutes |
| --- | --- | --- | --- | --- | --- |
| Gemini 3.8 Flash alone, standard 20 | 20/20 | 0 | 0 | 1.17M | 4.8 |
| Gemini 3.8 Flash alone, hard 4 | 4/4 | 0 | 0 | 1.98M | 10.2 |
| Gemini 3.8 Flash alone, large 1 | 1/1 | 0 | 0 | 1.78M | 7.8 |
| GPT-6.1 Sol alone, hard 4 | 4/4 | 32k | 151k | 0 | 1.7 |
| GPT-6.1 Sol alone, large 1 | 1/1 | 42k | 171k | 0 | 2.3 |
| Claude Opus 4.6 alone, first 5 standard (then out of quota) | 5/5 | not tagged | 113k | 0 | 0.8 |

**The cheap worker was as capable as the experts on this suite.** Gemini Flash
passed all 25 tasks. It was slower (5 to 10 minutes against 1 to 2) and read
far more tokens, but those tokens come from the plentiful quota.

## Team configurations

| Configuration | Passed | Expert tokens, fresh | Expert tokens, all | Worker tokens, all | Minutes |
| --- | --- | --- | --- | --- | --- |
| `factory` (plan first), multi-part 4 | 4/4 | 23k | 63k | 2.04M | 9.9 |
| `factory-wf` (older routing, planned), hard 4 | 4/4 | 30k | 106k | 1.83M | 22.5 |
| `factory-wf`, large, one task planned | 1/1 | 31k | 76k | 2.96M | 13.6 |
| `factory-wf`, large, four tasks, two in parallel | 1/1 | 32k | 77k | 7.86M | 29.5 |

What these showed, and what changed because of it:

1. **Planning cost nearly as much expert effort as doing the task.** A plan
   took 23-31k fresh expert tokens; Sol solved a whole hard task with 32k.
   Every plan on tasks of this size was a single task. So `factory-wf` now
   plans only clearly large requests (5+ numbered parts, 300+ words, or 8+
   named files), and every suite task except the large one starts with a
   worker and no plan.
2. **Splitting did not pay at this scale.** The four-task shop plan cost more
   time (29.5 against 7.8 minutes) and four times the worker tokens of a single
   worker, because each worker reads the code again and only two tasks could
   run side by side. Parallel work stays available for large requests but is
   not a win yet.
3. **The tester matters once workers are cheaper.** With Gemini Flash high
   the tester never found a problem (five verdicts, all pass). With Flash low,
   a worker passed the visible checks with a broken cache and, without a tester,
   that wrong change was accepted: the hard tasks scored 3/4. With the tester
   on, its findings (a load that failed synchronously poisoned the in-flight
   map; a cron range `SUN-SUN` read as the whole week) went back to the worker,
   and the same low-effort worker scored 4/4. The tester runs on Gemini, the
   cheap quota, so it stays on.
4. **Low effort first is much faster.** Gemini Flash low finished the four
   hard tasks in 7.5 minutes in total (Flash high alone: about 40). The worker
   ladder in `factory-wf` starts every task at low effort and climbs to high
   only when the engine sees the worker is stuck.
5. **Escalation is cheaper as advice.** When a worker is stuck, the expert first
   reads the worker's code and the exact failures and returns a short diagnosis
   and steps; the worker applies them. The expert takes over only if that
   fails. A per-run expert budget (250k fresh tokens) caps the worst case.

## Cost in one unit

Recorded tokens priced at API list prices of 2026-11-11
(`docs/reference/api-pricing-2026-11-11.md`, `src/usage/prices.ts`). This is an
estimate of what the same tokens would cost on the pay-per-token APIs. Nothing
was paid: all runs used subscriptions.

Hard tasks, per task:

| Configuration | Passed | API estimate | Minutes |
| --- | --- | --- | --- |
| GPT-6.1 Sol alone | 4/4 | $0.10 | 1.7 |
| Gemini Flash low alone, no tester | 3/4 | $0.08 | 1.9 |
| Gemini Flash high alone | 4/4 | $0.50 | 10.2 |
| Flash low worker + Flash high tester | 4/4 | $0.62 | 13.0 |
| `factory-wf` with the ladder and tester | 4/4 | $0.70 to $0.82 | 15 to 17 |

Other tasks: Flash high alone averaged $0.25 per standard task. On the large
task: Sol alone $0.14, Flash high alone $0.34, `factory-wf` $0.72 as one task
and $1.87 split into four.

**By API prices the factory costs 6 to 8 times more than the expert alone, not
less.** Two reasons:

1. Gemini 3.8 Flash is not cheap enough. Per token it costs about 37% of Sol
   ($0.75 and $3.75 per million against $2 and $10), while at high effort it
   uses 6 times the fresh input, 15 times the cache reads and 20 times the
   output that Sol does for the same task.
2. The tester is most of the bill: about $0.54 of the $0.62 per hard task.

The published analysis of "cheap first, expert on failure" says the same thing:
it pays only when the cheap attempt costs a small fraction of the expert's. Here
the "cheap" attempt costs five times the expert's.

So the two frames disagree:

- **Subscription quota** (how v0.1 was built and run): Gemini quota is separate
  from ChatGPT quota and larger, so keeping the expert idle protects the scarce
  one. Even so, three parallel suite runs emptied the Gemini 5-hour window.
- **API cost** (the unit in the project's goal): the Gemini presets lose.

The prices predicted that a worker in the GPT-6 Luna class ($0.10 and $0.50 per
million, a twentieth of Sol) would win if it could do the tasks. That was
measured the same afternoon.

## A truly cheap worker: GPT-6 Luna

GPT-6 Luna through Codex, medium effort, alone (`solo-luna`), and as the worker
and tester of a team with Sol as the expert (`factory-luna`: Luna low, then Luna
high, Luna tester, Sol on failure).

| Configuration | Tasks | Passed | API estimate per task | Minutes per task |
| --- | --- | --- | --- | --- |
| Luna alone | all 25 | 25/25 | $0.004 | 0.9 |
| Luna alone | hard 4 | 4/4 (twice) | $0.004 | 1.1 |
| GPT-6.1 Sol alone | hard 4 | 4/4 | $0.102 | 1.7 |
| `factory-luna` | hard 4 | 4/4 | $0.012 | 2.4 |
| Luna alone | large 1 | 1/1 | $0.007 | 1.7 |
| GPT-6.1 Sol alone | large 1 | 1/1 | $0.144 | 2.3 |
| `factory-luna` (Sol plans it) | large 1 | 1/1 | $0.094 | 5.6 |

Codex's own session files confirm the runs used `gpt-6-luna`.

What this shows:

1. **The goal is met on this suite, with a large margin.** `factory-luna`
   matches the expert's pass rate on the hard tasks at 12% of the expert's cost.
   Luna alone does it at 4%, and faster than Sol. The whole 25-task suite cost
   an estimated $0.09 and 22 minutes on Luna alone; Gemini Flash alone took
   about two hours and an estimated $5.
2. **The suite is too easy to say more.** The cheapest listed model passes all
   25 tasks alone, every time so far. No result here can show a team beating a
   single cheap model, because there is nothing left to gain. A harder benchmark
   is now the most important missing piece.
3. **Per-token price mattered less than tokens per task.** Luna used about as
   many tokens as Sol (20k fresh input, 80k cache reads, 2k output per hard
   task). Gemini Flash used 6 to 20 times more. A model's price list does not
   predict this; it has to be measured per model and tool.
4. **The tester is cheap here and still found things.** On the hard tasks a
   Luna review cost $0.003 to $0.008. It rejected two changes from the
   low-effort worker that had passed the project's checks (a load not shared
   when the key is set mid-load; weekday names mapped to wrong numbers), and the
   worker fixed both. Whether those two would have failed the hidden tests was
   not measured.
5. **Planning is again the expensive part.** On the large task the Sol plan cost
   $0.058 of the $0.094; Luna alone did the whole task for $0.007. The expert
   was not needed for anything else in these runs.

Not measured yet: how much ChatGPT subscription quota Luna uses (the owner's
usage panel will show it), repeat runs of `factory-luna`, and anything on tasks
hard enough to make Luna fail.

## E1 to E5

| | Criterion | Result |
| --- | --- | --- |
| E1 | Three full-suite runs of the default team preset with zero engine failures | Pass: `factory-luna`, `e1-luna-1..3`, 75/75 tasks passed, 0 engine failures, 28 to 39 minutes per run. (The earlier Gemini E1, `e1-final-1..3`, was stopped unfinished when the default changed: 10 passed, 0 engine failures.) |
| E2 | Team passes at least as many tasks as the expert alone, minus one | Pass: 25/25 in every run; GPT-6.1 Sol alone passed 5/5 on the hard and large tasks |
| E3 | Expert share at most half of the expert alone | Pass: expert share 0 to 1% of tokens. Estimated API cost $0.008 to $0.011 per task (hard tasks $0.010 to $0.014, against $0.102 for Sol alone; the large task $0.075 to $0.086, against $0.144) |
| E4 | A run stopped by a crash or Ctrl-C resumes and finishes | Pass: `kill -9` and Ctrl-C both resume to a finished, checked run, on the final engine (`evals/kill-resume.ts`) |
| E5 | Trivial requests never start an orchestrator | Pass: both trivial tasks route to a single worker under every team preset; covered by tests |

## Engine reliability fixes found by measuring

Every one of these was found by a live run, not by the unit tests:

- Antigravity and Codex sometimes print their final event and never exit. The
  engine now stops a tool 10 seconds after its final event and keeps the result.
- Connections to the model APIs drop or stall. One retry on network errors, and
  a 10-minute idle timeout for a turn that prints nothing.
- Codex runs commands in their own process group, so cancelling left them
  running. The engine tracks and stops the whole process tree.
- A crash used to lose the in-progress turn. Turns are recorded when they
  start, so resume knows what happened.
- Claude 4.6 through Antigravity ran out after about five tasks and then asked
  for paid credits. Models that hit a limit go on a cooldown until their reset
  time and the next model in the role's list takes over.


```bash
node src/cli/main.ts eval --preset solo-sol --kinds hard,large --name expert-alone
```

```bash
node src/cli/main.ts eval --preset factory-wf --name factory-wf-run
```

```bash
node src/cli/main.ts eval --preset solo-luna --name base-solo-luna
```

```bash
node src/cli/main.ts eval --preset factory-luna --kinds hard,large --name hl-factory-luna
```

```bash
node src/cli/main.ts eval compare base-solo-flash expert-alone factory-wf-run
```

Note: a full `factory-wf` run takes two to three hours, mostly Gemini time.
